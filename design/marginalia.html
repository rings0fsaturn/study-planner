SECTION 01

Principles

Six commitments the design makes to the learner. Every component, color, and copy decision below is downstream of these. When a decision feels uncertain, return here.

01 / 06
Mirror, not enforcer
The UI shows learners where they stand — never nags, gamifies, or guilts. Color is honest: green is on track, rust is behind, that's it. No streak-at-risk fireworks. No engagement hooks. The product trusts the user to act on what the mirror shows.
02 / 06
Paper, not glass
Cream backgrounds, hairline rules, soft shadows. Surfaces feel laid down, not floated. No frosted glass, no neon glows, no dark-mode-by-default. Studying is a slow, considered activity; the app should feel that way too.
03 / 06
Editorial, not appy
A serif headline (Fraunces) leads. Stats borrow the same serif so numbers feel weighted, not flashy. Mono is reserved for metadata — labels, timestamps, units. The app reads like a quiet field journal, not a SaaS dashboard.
04 / 06
No AI tells
No sparkle icons, no robot avatars, no "✨ powered by AI" flair, no chat bubbles. The intelligence shows up in what the app does well — accurate estimates, sharp summaries, useful re-plan options — never in what it calls itself.
05 / 06
Decisions stay with the user
The app never silently shifts the deadline, skips materials, or recalibrates pace without the user's say-so. When a choice is needed, it appears as a small set of clearly-priced options. Never a free-text prompt; never an autopilot.
06 / 06
Quiet by default, sharp when it matters
Most of the UI is monochrome paper-and-ink. Color is reserved for the few moments where it carries meaning — the "Up next" card, a behind-pace verdict, a re-plan call to action. If everything is emphasized, nothing is.

E. Dark mode

Deferred to a future version. The current palette is bright, warm, and explicitly reading-room — a dark mode would change the brand more than it would solve a real problem. Reconsider only if user research surfaces it as a barrier (likely candidates: late-night studying, OLED-screen fatigue).

SECTION 05

Elevation

Two shadows, plus one for modals. If you find yourself wanting a third level, the hierarchy is wrong — fix the hierarchy, don't add a shadow. Marginalia is paper, not glass.

Flat
none, just a border
Default for cards and list rows. The most common state.
Shadow sm
--shadow-sm
Buttons. Cards that need the slightest lift to read as tappable.
Shadow md
--shadow-md
Hover state for primary cards. Sticky bars on scroll.
Shadow modal
--shadow-modal
Dialogs, popovers, the phone frame in mockups. Used sparingly.
Rule
Shadows are warm — built from the ink color at low opacity, not pure black. A pure-black shadow on cream paper looks like a Photoshop drop-shadow; a warm shadow looks like an object resting on a desk.
SECTION 06

Movement should be small and short. A slow, considered product shouldn't feel performative. Most transitions are 160–240 ms. Anything longer needs justification — and it's almost always wrong.

H. Anti-patterns

Things that look fine in isolation but fight the system. The text below isn't exhaustive — it's the list of mistakes most likely to slip in during component design.

Don't
Use weight 700+ on any face, anywhere.
Use mono for body prose or for stat numbers (stats are serif).
Use italic Inter Tight — italics are a Fraunces-only move.
Use display sizes without adjusting opsz — Fraunces at 48px with opsz 9 looks broken.
Use proportional numerals in stats — they jitter when values change.
Use ALL CAPS in body sans — caps belong to mono labels only.
Use emoji as decoration in headlines or stats.
Set body prose line-height tighter than 1.5 — this is a reading product; reading needs room.

SECTION 12

Voice & copy

How the product talks to the person using it. Calm, plain, never punitive. The PRD is explicit that the voice is part of the product — generic SaaS copy would undo the work the visual design does. Treat every line of UI text as a writing assignment.

A. Five voice principles
01 / 05
Calm and concrete
Short sentences. Specific numbers when they help. No buzzwords, no caps for emphasis, no exclamation marks anywhere. The italic accent is the only emphasis Marginalia owns.
02 / 05
Plain over technical
"Estimate," not "ML-derived projection." "Backed up," not "synced via blob upload." If a phrase requires the user to know our architecture to understand it, we picked the wrong phrase.
03 / 05
Never punitive
No "you missed," "you broke your streak," "you're falling behind on your goals." The mirror tells the truth without judgment. "Behind" is fine; "failing" is not.
04 / 05
Honest about limits
When sync fails, we say so and we say what's safe. When we couldn't fetch a URL's metadata, we say so and let the user fill in the gaps. Vague reassurance is worse than concrete bad news.
05 / 05
The user has agency
We offer, the user chooses. "Want to extend the deadline?" not "We've extended your deadline." The product never silently does the thing for them, and the language never pretends otherwise.

One italic phrase per screen, never more. Allowed in: a single emphasized word inside a display headline ("a quiet companion"); an italic Fraunces sub under a display headline; the weekly-narrative pull-quote. Anywhere else, it looks like a designer flourish.

Rule
Terracotta button text passes AA at 16 px and above — which is exactly the size the button system uses. Don't ship terracotta as text below 14 px on cream paper; switch to terracotta-d for safety. Verified contrast wins over assumed contrast.
B. Touch targets · minimum hit zones
Mobile · 44 × 44 min
Visible button + 8 px invisible padding around it = 44 px minimum hit zone (Apple HIG, WCAG).
Desktop · 32 × 32 min
Cursor input is more precise. Smaller controls are acceptable on desktop, but never smaller than 32 px on the shortest dimension.
Toggle · 38 × 22 visible
Hit zone extends ~10 px beyond the visible track on every side, satisfying the 44 px rule.
C. Focus states · always visible, always 2 px ink
Tab through these — focus is always visible
Rule
Focus is delivered via :focus-visible only — keyboard users see it; mouse users don't. Never disable focus rings to "clean up" a design. The 2 px ink ring with 2 px offset is part of the brand, not an afterthought.
D. Keyboard navigation
Tab order
Follows the visual reading order. Custom tabindex values higher than 0 are forbidden — they break expectations every time.
Modal focus trap
When a modal opens, focus moves to the first interactive element inside; tabbing wraps within the modal until it closes.
Escape closes modals
Always. Returns focus to the element that opened the modal.
Enter submits forms
Within a form, Enter triggers the primary submit button. Choice options use Space (button semantics).
Arrow keys in chips
Segmented chip rows behave as a radiogroup — left/right arrows move selection without leaving the group.
Skip-to-content
Every page has a skip-link as the first focusable element, jumping past the nav to the main content area.
E. Reduced motion · prefers-reduced-motion
Streak fill
Cell still changes color on log; the scale-pulse spring is removed. Color is the signal; motion is decoration.
Timer pulse
The moss dot stops pulsing and stays at full opacity. The "session is alive" signal is the running clock, not the pulse.
Processing dots
Three dots become three static, dimmed dots. The progress checklist still updates as items resolve.
Narrative streaming
The full text appears at once when the LLM response completes — no progressive character-by-character render.
Tab title flash
The title still alternates — but the favicon dot is the primary signal. Users who turn off motion can rely on the static dot.
Hover transitions
Color shifts on buttons stay (160 ms is below the threshold most users find disruptive, and they're functional, not decorative).
F. Color isn't the only signal
Stats
Color (moss / terracotta / rust) is paired with a mono-caps label below ("studied · on track" or "projected · attention"). A user who can't perceive the color difference still gets the meaning.
Choice option · selected
2 px ink border, not just a color shift. aria-checked="true" communicates the state to screen readers.
Form errors
Triple-encoded: red field border, red helper text below, and an icon prefix on the error message. Removing color still leaves two clear signals.
Streak ramp
Color intensity carries the most information, but the row's left-to-right time order is itself ordinal. Each cell exposes aria-label with the date and minute count.
Burn-up chart
Three lines distinguished by color AND line style — solid, dashed-thin, dashed-thick. Legend includes both swatches and labels.
G. Screen-reader patterns
Active timer
aria-live="polite" on a hidden region announces the elapsed time at 1-minute intervals — never every second (would overwhelm). The visible timer continues updating per second.
Toggle
aria-pressed reflects on/off state. The toggle is a <button>, not a checkbox — semantically it's an immediate action.
Modal
role="dialog" + aria-modal="true" + aria-labelledby pointing at the modal title. Focus moves into the dialog on open.
Form fields
Every <input> has a real <label> association. Helper and error text use aria-describedby. Errors use aria-invalid="true".
Nav
The current destination uses aria-current="page". Mobile bottom bar items have aria-label matching their visible text.
Sync status
Sync indicator changes use aria-live="polite". "Sync failed" announcements get an additional role="status" so users hear the failure.
Streak cells
Each cell: aria-label="April 27, 2026 — 78 minutes studied". The grid container has role="grid" with row and column header semantics where relevant.
Charts
Each chart has a hidden text summary above it (the same content as the headline mono caps line — "Hours studied vs plan · Wk 4 of 8") plus an accessible data table fallback that's reachable via a "Read as table" link below the chart.
H. Closing principles

Accessibility is not a layer applied at the end — it's part of how each component in this document is built. Tab order, focus states, semantic markup, and reduced-motion handling are specified at the primitive, so screens that compose primitives inherit the work for free.

Where the system falls short of full AAA — terracotta button text at smaller sizes, color-as-primary-signal in some chart elements — it's noted and designed around. Honest about limits applies to accessibility too.

Dark mode is deferred but the path is clear: every component references semantic tokens, never raw palette values. A future @media (prefers-color-scheme: dark) swap of the semantic token map would carry every component along without per-component changes. The decision to defer is about brand fit and scope, not technical debt.
