One question is the unit
  • An assessment holds questions. Each attempt grades one question.
  • An attempt carries the skill tags of its question, so the result points at a topic.
  • A retry writes a fresh attempt. The old one stays.
The server grades
  • Objective answers grade in code, so the result cannot drift.
  • Written answers grade against a rubric, composed by weight.
  • The answer key and the rubric stay on the server.
Grounded in the material
  • Every question cites chunks of the learner's own material.
  • The server checks each cited chunk against the retrieved set.
  • The chapter scope keeps the context inside the chosen pages.
The mastery step is reserved, not built. Ticket #43 owns the mastery signal and the adaptive difficulty.

05 / 11
05How written answers get gradedNew slice
A written answer has no single correct string. The model writes a rubric with the question, and the server grades the answer against that rubric.
PartHow it works
CriteriaThe model authors 2 to 6 criteria and gives each a weight.
ScoreThe provider scores each criterion. The server multiplies each score by its authored weight and composes one score from 0 to 1.
VerdictA score at or above 0.6 marks the skill correct. Both grading arms use this same threshold.
SecrecyThe rubric, the reference answer and the criterion internals stay behind a column-level grant. The learner sees a criterion label, its weight, its score and its feedback.
FailuresUnusable input fails closed, because a retry cannot repair it. A timeout, a quota stop or a malformed answer returns the job to the queue.
Live pass 4 of 4 in 4.3 minutes with real model grades at desktop and mobile. One contract dry run used 565 tokens in 10.9 seconds.
Source: #41 P3 dry run and P5 live pass (2026-09-10 and 2026-09-11). Code is complete from P1 to P5. The ticket close and the archive are still open.

06Every question asked about the exam, not the bookDefect and fix
What we measured
25 / 25
  • Every generated question asked about the examination or the document.
  • 5 of 5 retrieved passages were cover, contents page or index.
  • Only 8.5% of the corpus is exam material.
Why it happened
  • The retrieval query was the material title.
  • The title matches the cover, the contents page and the index, so those passages won both halves of the search.
  • Nothing in the prompt blocked a question about the document itself.
What we changed
  • The title left the query. It stays in the prompt as document context.
  • The prompt now blocks meta questions and asks for a concept or an application.
  • The learner picks a chapter or a page range. Pages ride from extraction to chunks to retrieval.
Live result

A Chapter 5 scope keeps every citation inside PDF pages 156 to 213. A thin range widens and warns instead of failing. The viewer shows 572 pages in one scroll, with Fit and zoom, and it decodes the 587 JBIG2 images that pdf.js had been dropping.

Sources: retrieval-drift transcript (2026-09-11) · P4 scoped-generation live pass · P6 viewer pass and image fix (2026-09-12).

07What the live runs caughtHonest status
Defect 1
The retry asked for the wrong shape

A failed written generation retried as objective. The retry read the family from the first question, and a failed generation has no questions. The read route now returns the stored recipe.

Defect 2
A citation named a chunk that does not exist

The model invented a chunk id, and 5 of 14 written generations failed on it, the same id four times in a row. The response schema now binds the citation id to the retrieved ids.

Defect 3
Every diagram vanished, and no test saw it

pdf.js decodes JBIG2 images with a wasm module. Nothing set the module path, so 587 images dropped with one console warning each while the text and the ink stayed. The app now serves the decoders.

Defect 4
Our desktop test was a phone test

One viewport setting applied to every test in the file, so a desktop scenario ran at 375 pixels for a whole phase. The viewport now sits inside the block that needs it.

Why we show them
Defects 1 and 2 came from the live pass on the real provider, not from unit tests. Defect 3 came from the learner's own material. Each one now has a test that fails if it comes back.
Records: #41 P5 live-found defects (2026-09-11) · #62 P6 image fix and viewport correction (2026-09-12).

09Demo: from a chapter to a graded answerDemo
  1. Sign in and open Materials.
  2. Open a ready material. Note the chapter list and the page count.
  3. Pick a chapter and Generate assessment.
  4. Answer the question. The server grades the attempt.
  5. Open the review. Show the score, the explanation and the citations.

  8. Open the viewer. Scroll, zoom, and jump to a chapter.
Watch for
  • Citations stay inside the chosen chapter.
  • The answer key never appears in the browser.
  • A retry keeps the old attempt next to the new one.
  • An image-heavy page renders its figures.
