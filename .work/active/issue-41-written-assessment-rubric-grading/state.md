## Pitfalls & rules
- Must honor map #4 capstone principle: feature-rich and complete, no MVP deferral.
- Redaction is a hard gate (extends #40 AC4): authored rubric text / reference answers must never reach the browser; `answer_block` stays service_role-only. The public written surface is criterion label + weight + score + met + feedback only.
- Before `CREATE OR REPLACE`-ing a Postgres function, grep the whole `apps/app/supabase/migrations/` directory for that function name and copy its **most recent** body: plpgsql bodies are parsed only at first execution, so a stale copy applies silently and fails at runtime. This is exactly how 027 dropped 024's `::uuid` cast and broke every live accept (42804); 028 repaired it.
- Any migration that re-creates the question-accept RPC must keep passing `subtype` and must keep `answer_block` out of the `authenticated` column grant (022 revoked the table-level SELECT; re-issuing a broad grant would re-leak the hidden block).
- `openapi.yaml` uses YAML flow mappings: a colon-space inside an unquoted `description` scalar is a parse error. Write descriptions with semicolons (the file's existing style).
- Contract fixtures come in two kinds: `manifest.json`-mapped ones are JSON-schema files validated in bulk; OpenAPI-inline ones are validated per-fixture in `test_contracts.py` via `_validate_against_openapi`. The JSON-only manifest loader cannot reference `openapi.yaml`.
- Fixtures are read with `encoding="ascii"` — no em dashes or non-ASCII characters in fixture files.
- Retry = fresh observation (map #10): new clientAttemptId row, append-only history, never overwrite.
- #41 rendering is constrained by the #40 review surface — fill its written treatment, do not fork a second surface.
- Live grading needs the ingestion worker (`bash scripts/run-detached-ingestion-worker.sh`; `full` profile does not run it).
- Live mutation specs on the shared account must run `--workers=1` (rule 16 credentials + managed runtime).
- TS control-flow narrowing does not carry into hoisted nested functions inside effects — re-guard nullables inside async closures; annotate untyped `.map` arrays (e.g. `AttemptRecord[]`) or literal unions widen to string.
- `expectedLengthWords` is part of `WRITTEN_SCHEMA` but is deliberately not persisted (no contract field, no column); do not read it from a question row in P4.
- The tree's ruff baseline is not clean (3 x I001 in the #39 grading test files + 1 x E501 in `routers/assessments.py`, at line 168 in HEAD and 176 after the P5 route change) — pre-existing, not phase fallout. Fix the lints a phase *introduces* in the files it edits; leave the rest.
- The provider request needs a schema name (`response_format.json_schema.name`); it is now a constructor parameter. Do not reintroduce a hardcoded `grounded_mcq` or written grading will be served a generation schema name.
- Provider criterion judgments are matched to the authored rubric **positionally**, with an exact count required; never match on the returned criterion text (it is a paraphrase and the authored label is the public truth).
- Never publish the model's `met` flag: derive it from the criterion score at the τ≈0.6 threshold so the breakdown can never disagree with the overall score.
- A successful written grade must not set `publicFeedback` — `reviewModel.ts:199` prefers it over `explanation`, so setting it hides the rubric narrative from the #40 review surface.
- Grading failure classes carry opposite handling: `GraderInputError` = fail closed (unusable input, retry cannot help), `RubricResponseError` / retryable provider outcome = redeliver. Do not collapse them into one except-branch.
- Validate the answer text *and* the rubric before the provider call; both checks exist so unusable input costs no provider budget.
- **The detached worker does not hot-reload.** uvicorn's `--reload` covers the HTTP service only; after any change under `services/intelligence/app/` the ingestion/grading worker must be restarted (`kill <pid>`, then `setsid nohup bash scripts/run-detached-ingestion-worker.sh`) or the live run silently exercises the old code — this cost a full live re-run on 2026-09-11.
- A live written generation needs the GPU sidecar on :8200 as well as the runtime and the worker; a stopped sidecar fails every generation with `embedding sidecar request failed: [Errno 111] Connection refused`.
- `pnpm test:e2e -- <spec> --project=app --workers=1` silently DROPS every option after `--` (the CLI treats them as test-file filters): plain `pnpm test:e2e <spec> --project=app --workers=1`, no separator, or every project runs on as many workers as the config allows.
- Playwright restarts the worker process after a failing test, which resets module state — never share mutable state (like an assessment id) between live scenarios: the dependent tests silently become SKIPS (which look like "not verified", not failures). Each scenario must be self-contained.
- Never derive a retry's request shape from data the failed attempt does not have: a failed generation has no questions, so the family/band/tags must come from the stored `recipe` the read route now echoes (`AssessmentDetail.tsx` retry).
- Never leave a provider-facing id free-form: `chunkId` must stay enum-bound to the retrieval context (`mcq_schema`/`written_schema` take the ids). Since 2026-09-11 both schemas are built per message; do not reintroduce a module-level schema constant.
- A `citation_missing` drop is deliberately NOT repairable (`validation.py` + `test_generation_worker.py`), so an unbound `chunkId` fails the whole generation and every retry repeats it (measured live: 5 ok / 14 written attempts, the same invented id four times).
- `GENERATION_TIMEOUT_MS=30000` is not an end-to-end deadline: a live provider call measured 146.6 s (`generation_telemetry.latency_ms=146644`) before reporting `provider_error`. Size live waits accordingly (the spec waits 300 s per authored attempt).
- `innerText` reflects CSS `text-transform`, so the written answer label reads uppercase (`YOUR ANSWER (SHORT ANSWER)`); assert case-insensitively.
- The `Attempt history` block only exists once a question has actually been retried, so a retry scenario must settle on the graded card first.
- `.work/specs/test-login-cred.txt` values must be stripped of backticks as well as quotes when read into a shell probe, or sign-in answers `invalid_credentials` and looks like a Supabase outage.

- Taking stays in AttemptTaker per #40 D-04; its verified submit/poll/retry phases are reused, not re-implemented.
- The model authors `subtype` (no recipe field, no config control): D-01 keeps `subtype` in the authored visible payload and D-04 scopes the config picker to `formats` only. Consequence: exercising both subtypes in the P5 live pass needs a re-roll or a topic steer.
- Rubric contract: `WRITTEN_SCHEMA` requires 2..6 criteria (the schema steers away from a holistic rubric), while the hard gate accepts >= 1 so a single-criterion-but-usable rubric grades instead of dropping the assessment; weights must sum to 1 within 0.02; only `criterion`/`weight`/`maxPoints` reach `answer_block`.
- Deviation procedure kept from P1: additive deviations are recorded in the phase's plan Notes block rather than reopening verified decisions; applied migrations are never rewritten (027 stayed as pushed, 028 repaired it).
- The written-answer shape gate is server-side in the submit route (`{ text }` non-empty, <= 20000, else 400) and is mirrored client-side in `AttemptTaker` (blank text keeps Submit disabled; an over-long answer blocks with a hint).
- Grading retry policy (P3): retryable = provider timeout / quota / unavailable / malformed payload (message redelivered, attempt left in flight); terminal = safety block / credentials / unsupported / generic provider error, plus unusable input — these fail the attempt closed (status `failed`, score 0, reason in `publicFeedback`, job non-retryable). Rationale: never loop the queue forever, never leave the learner on an endless grading state, and keep the arm's posture consistent with #39's malformed-input handling.
- Published criterion `weight` is the criterion's share of the rubric total (renormalized), so a rubric whose authored weights drifted still publishes contract-valid weights that sum to 1 (2026-09-10).
- The assessment read echoes the stored `recipe` so the client can re-request the same shape after a failed generation (2026-09-11, P5 fix 1): the retry had been inferring the family from `questions[0]`, which does not exist on a failure, and so silently re-requested `objective` — the exact opposite of what its own comment claimed.
- Both generation response schemas bind `citations[].chunkId` to the retrieved chunk ids by enum, built per message (2026-09-11, P5 fix 2). Prompt-level instruction is not a bound: the model must be structurally unable to emit an id outside the context. This applies to the objective arm too (same schema shape, lower observed hit rate).
- `citation_missing` stays non-repairable even with the enum in place (the enum makes it unreachable rather than repairable); do not "fix" the drop path by widening the repair policy.
- Live scenarios are self-contained (each generates its own assessment) because a failing test resets Playwright's worker process and would otherwise turn dependent scenarios into silent skips (2026-09-11).
