## Pitfalls & rules
- AC4 is a hard gate: the prototype must never display hidden answers, rubrics, reference solutions, or hidden tests as client content — mocks must not even contain `answerBlock`/`correctIndex` keys (mirror issue-38 redaction grep check).
- Dev-only route guard: `import.meta.env.DEV && <Route ...>` exactly like `App.tsx:103-107`; never ship the prototype route to production.
- Rule 12: write the route path without the `/study` prefix (`/assessment-review-prototype`); the basename is a deployment concern.
- Throwaway scope (map #4 destination override): no persistence, no new event kinds, no Dexie bump (rules 30/31), no service calls, no tests beyond a build/typecheck smoke.
- Wayfinder prototype tickets are HITL: the human picks the surface; the agent must not decide the recommendation alone.
- Avoid giving a tablist arrow navigation while `PrototypeSwitcher` is mounted: its global ArrowLeft/ArrowRight listener cycles `?variant=` and re-renders the shell, dropping focus. Guard is `activeElement.closest('[role="tablist"]')` in the switcher's key handler (PrototypeSwitcher.tsx:27-40).
- PLAN 3.4 says the `partial` state shows "the ungraded one shown as pending", but D-04 and the fixture define that question (`q-part-3`) as still **processing** — the panel therefore renders the `aria-busy` skeleton, which is the honest in-flight treatment; `pending` remains reserved for questions whose grading has not started.
